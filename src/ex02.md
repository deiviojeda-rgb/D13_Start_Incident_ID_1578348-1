## Время

### 4. Сколькими способами в журнале записано время и сколько строк в каждом?

**Ответ:**format	count
YYYY-MM-DD HH:MM:SS	986
DD.MM.YYYY HH:MM:SS	38

**Чем получено:**

```SQL
SELECT
  CASE
    WHEN ts LIKE '____-__-__ %' THEN 'YYYY-MM-DD HH:MM:SS'
    WHEN ts LIKE '__.__.____ %' THEN 'DD.MM.YYYY HH:MM:SS'
    ELSE 'other'
  END AS fmt, COUNT(*)
FROM access GROUP BY fmt ORDER BY fmt;
```

### 5. В каком часовом поясе записано время в журнале доступа? В каком — в файле тикетов? Откуда это известно?

**Ответ:**Журнал доступа записан в московском времени (UTC+3, MSK)
IP 10.8.14.21/22/23 — «офис «Привал», Москва» в geoip; рабочие сессии начинаются в 05:00–06:00 по ts — это утренний старт рабочего дня в Москве (UTC+3), а не 02:00–03:00, как было бы при UTC.

mfa_reset в 20:31:18 и вход a.sokolov в 23:55:04 — типичное «поздним вечером» по MSK; при UTC это было бы 17:31 и 20:55, что менее правдоподобно для «после работы».

В строке login у a.sokolov от 12.09 00:01:14 стоит mfa_enrolled_at=2026-09-11T20:31:18Z — это UTC (Z), и он ровно на 3 часа меньше локальной метки 2026-09-11 20:31:18 в поле ts того же события mfa_reset. Разница 3 ч = UTC+3 ⇒ журнал в MSK.

**Чем получено:**

```sql
SELECT a.ts, a.ip, g.city, g.org
FROM access a JOIN geoip g ON a.ip=g.ip
WHERE a.action='login' AND g.org LIKE 'офис%'
ORDER BY portm(a.ts) LIMIT 5;

SELECT ts, detail FROM access
WHERE action='login' AND detail LIKE '%mfa_enrolled_at=%';

SELECT ts, detail FROM access WHERE action='mfa_reset';
```

### 9. Какие адреса впервые появляются в журнале начиная с 9 сентября? Сколько раз встречается каждый?

**Ответ:**Новые IP с 09.09.2026 (в порядке первого появления):

ip	первый раз	всего вхождений
45.132.19.88	2026-09-09 01:17:09	2 (api_auth, read_config)
185.220.101.45	2026-09-12 00:01:14	4 (login, search_client, export, logout) + 1 http_get с login='-' (итого 5 строк с этим IP)
Проверка: 176.59.208.33 появляется 11.09 в 23:55 — это тоже «начиная с 9 сентября», и он встречается 3 раза (login, view_order, logout). Добавь его в таблицу, если считать «с 9 сентября включительно»:

ip	            первый раз	        всего
45.132.19.88	2026-09-09 01:17:09	2
176.59.208.33	2026-09-11 23:55:04	3
185.220.101.45	2026-09-12 00:01:14	5

**Чем получено:**

```sql
WITH first_seen AS (
  SELECT ip, MIN(portm(ts)) AS first_ts
  FROM access
  WHERE ip <> ''
  GROUP BY ip
)
SELECT a.ip, f.first_ts, COUNT(*) AS cnt
FROM access a JOIN first_seen f ON a.ip=f.ip
WHERE f.first_ts >= '2026-09-09 00:00:00'
GROUP BY a.ip, f.first_ts
ORDER BY f.first_ts;
```

### 11. Есть ли в журнале обращения без всякой аутентификации и обращения по сервисному токену? Когда и к чему?

**Ответ:**Ответ: Да.

Без аутентификации (auth_method='none'): 1 событие — 2026-09-12 00:19:47, login='-', IP 185.220.101.45, http_get /backup/clients_2026-06.csv, result=200, bytes=367587. Это прямое скачивание бэкапа без логина.

По сервисному токену (auth_method='token'): 1 событие — 2026-09-09 01:17:09, login='-', IP 45.132.19.88, api_auth /api/config, detail=token_id=EXP-9f3a7c21b8e4. Следом, в 01:17:12, — read_config /api/config (1841 байт) в той же сессии s09901.

**Чем получено:**

```sql
SELECT portm(ts), login, ip, action, object, result, auth_method, session_id, detail
FROM access
WHERE auth_method IN ('none','token')
ORDER BY portm(ts);
```
